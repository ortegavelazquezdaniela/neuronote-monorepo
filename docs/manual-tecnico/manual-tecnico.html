1Descripción general

Objetivo. Ayudar a personas neurodivergentes y con sensibilidad sensorial a moverse por la ciudad sin sobrecargarse, con información honesta y una interfaz que se adapta a la persona.

Módulos

Principios de diseño

  • Honestidad de los datos: cada valor indica su origen (Pronóstico, Calculado, Sin verificar, Medido, Demostración). No se inventan lugares, certificaciones ni profesionales.
  • Diseño sensorial: sin parpadeos ni animaciones en bucle; respeta el movimiento reducido.
  • Privacidad: ubicación solo bajo petición y nunca guardada; telemetría anónima; sin conversaciones guardadas.
  • Presupuesto $0.00 MXN: solo herramientas y planes gratuitos.

2Arquitectura

Monorepo con tres aplicaciones: un frontend SPA, una API REST y un motor de auditoría, más servicios gestionados en la nube.

Navegador · React 19 + Vite (Vercel)Leaflet ← mosaicos de OpenStreetMap · Nominatim/Overpass (lugares) · OSRM (rutas) · Supabase Realtime (presencia pública) · Web Bluetooth (pulso) · wa.me
↓ HTTPS + JWT Bearer
API Node.js + Express 5Render · /api
helmet, CORS, rate limit, zod, Swagger
Motor PHP 8.3 (Docker)Render · ICAS, actas, sellos HMAC, panel pericial
APIs externas vía proxyOpen-Meteo (caché 15 min) · REST Countries (caché 24 h, clave en el servidor)
Supabase (PostgreSQL)Cuentas, perfil, favoritos, profesionales · RLS · Realtime
MongoDB AtlasNotas sensoriales · telemetría anónima del SOS (TTL 1 año)
TiDB Cloud (MySQL)Establecimientos, actas, profesionales, sellos · TLS

Flujo de una petición autenticada

  1. El frontend guarda el JWT en sessionStorage (se borra al cerrar la pestaña) y lo envía en Authorization: Bearer.
  2. La API aplica helmet, CORS con lista blanca, límite de peticiones y valida el cuerpo con zod.
  3. verifyToken comprueba firma, emisor y caducidad (2 h) y carga el rol.
  4. El controlador usa un repositorio inyectado (Supabase, MongoDB o memoria). Sin claves de nube, la API funciona en «modo memoria».
  5. Los errores 5xx nunca exponen detalles internos; los 400 devuelven la lista de campos inválidos.

Decisiones clave

DecisiónMotivo
Tres bases de datosPostgreSQL para datos relacionales con seguridad por filas; MongoDB para documentos flexibles y datos que caducan; MySQL porque el motor pericial usa PHP + PDO.
Proxy de APIs en el servidorLas claves (REST Countries) no llegan al navegador; la caché reduce llamadas a servicios gratuitos.
Nominatim antes que OverpassLos servidores públicos de Overpass se saturan; si ambos fallan se usa la última respuesta guardada (≤ 7 días).
Motor PHP en DockerLos hostings PHP gratuitos bloquean peticiones entre servidores; Docker en Render lo permite.

5Instalación y ejecución local

Requisitos

  • Node.js 20.19 o superior (probado con 22 y 24) y npm.
  • Git.
  • XAMPP (PHP 8.2+ y MariaDB/MySQL) para el motor de auditoría.
  • Opcional: cuentas gratuitas de Supabase y MongoDB Atlas. Sin ellas, la API funciona en memoria.

1. Clonar e instalar

git clone https://github.com/ortegavelazquezdaniela/neuronote-monorepo.git
cd neuronote-monorepo
npm install --prefix frontend
npm install --prefix backend

2. Configurar variables

cp frontend/.env.example frontend/.env.local
cp backend/.env.example backend/.env
cp audit-engine/.env.example audit-engine/.env

Completa los valores según el capítulo 6. Los archivos .env están en .gitignore y nunca se suben al repositorio.

3. Base de datos del motor PHP

C:\xampp\mysql\bin\mysql.exe -u root < audit-engine/db/schema.sql

4. Ejecutar (tres terminales)

ServicioComando (desde la raíz)Dirección
Frontendnpm run devhttp://localhost:5173
APInpm run apihttp://localhost:4000/api/health
Motor PHPnpm run audit:servehttp://localhost:8080
Storybooknpm run storybookhttp://localhost:6006
Si /api/health responde "users": "memory" o "notes": "memory", falta configurar Supabase o MongoDB: la API funciona, pero los datos se pierden al reiniciar.

9Motor de auditoría (PHP)

Aplicación PHP 8 independiente (audit-engine/) con PDO y sentencias preparadas reales, tokens CSRF, cabeceras de seguridad y archivos internos inaccesibles desde el navegador.

Índice de Confort Acústico y Sensorial (ICAS)

VariablePesoEscala (100 = mejor, 0 = peor)
Ruido promedio (dB(A))35 %35 dB → 100 · 75 dB → 0
Picos sonoros (dB(A))15 %60 dB → 100 · 90 dB → 0
Reverberación (RT60, s)15 %0.4 s → 100 · 2.0 s → 0
Iluminación (lux)20 %150–500 lux → 100; 0 si < 50 o > 1000; −30 con parpadeo
Aforo (personas / 10 m²)15 %0 → 100 · 3 → 0

Niveles: ≥ 75 alto (certificable) · 55–74.9 moderado · < 55 bajo. Fórmula propia y documentada en src/icas.php; no es una norma oficial.

Flujo de certificación

  1. El perito registra el acta en src/submit_audit.php (validación de rangos, CSRF, transacción).
  2. En el panel (index.php, HTTP Basic + password_verify) se aprueba o rechaza.
  3. Con ICAS ≥ 75 se emite el sello: folio y hash HMAC-SHA256 de los datos del acta con BADGE_SECRET, vigente un año.
  4. src/verify.php recalcula el hash: si alguien altera el acta en la base, responde "integrity": "alterado".

10Frontend

Organización (Atomic Design)

Átomos (botón, campo, interruptor, etiqueta de dato) → moléculas (grupos de opciones, gráficas) → organismos (mapa, formulario de notas, SOS, clínicas) → plantillas → páginas. Los estilos usan CSS Modules y los tokens de styles/tokens.css.

Estado y datos

  • Context API: PreferencesProvider (tema, fuente, tamaño, movimiento), AuthProvider (sesión JWT) y SosProvider (modal y atajo Alt + C).
  • Hooks propios: useAsync, useGeolocation, useHavens, useSensoryRoute, useWeather, usePsychologist, usePageMeta, useHeartRateMonitor, useDebounce.
  • Servicios: services/http.js centraliza fetch con tiempo límite, reintentos, caché y mensajes de error en español.
  • Notas: la misma interfaz (list, add, update, remove, clear) para el navegador (notesStore) y la cuenta (notesApiStore).

Rutas

Definidas en src/routes.jsx con React Router 7: carga diferida de páginas pesadas, ruta dinámica /oasis/:id, ruta protegida /perfil (RequireAuth) y página 404.

Accesibilidad y SEO

  • WCAG 2.2 AA (autoevaluación): 45 de 47 criterios aplicables; ficha en docs/accesibilidad-wcag-2.2.md.
  • Enlace para saltar al contenido, foco gestionado al navegar, controles de 44 px o más, sin scroll horizontal a 320 px.
  • usePageMeta: título, descripción, canonical, Open Graph y noindex por página; sitemap.xml y robots.txt generados en el build.

11Seguridad y privacidad

AmenazaMedida
Robo de contraseñasbcrypt (12 rondas); comparación con hash ficticio para no revelar qué correos existen.
SesionesJWT HS256 con emisor y caducidad de 2 h; guardado en sessionStorage.
Datos inválidos o maliciososzod en el servidor (y validación en el cliente); limpieza de caracteres de control; cuerpo máximo de 10 KB.
Fuerza bruta y abusoexpress-rate-limit por IP y por intentos fallidos.
Acceso a datos ajenosToda consulta filtra por el usuario del token; RLS en PostgreSQL niega el acceso directo desde el navegador.
Inyección SQLSupabase con consultas parametrizadas; PDO con ATTR_EMULATE_PREPARES = false.
XSS y clickjackingReact escapa la salida; htmlspecialchars en PHP; helmet, CSP y X-Frame-Options.
CSRF (panel PHP)Token por sesión y cookies HttpOnly + SameSite=Strict.
Exposición de clavesSecretos solo en variables del servidor; .env fuera de Git; el navegador solo recibe la clave publicable de Supabase.
Errores con información internaLos 5xx responden un mensaje genérico; Sentry (opcional) recibe solo el tipo de error y la ruta patrón.

Privacidad

  • La ubicación se pide solo al pulsar un botón y no se guarda; al clima se envían coordenadas redondeadas (~1 km).
  • La telemetría del SOS es anónima y respeta Do Not Track y Global Privacy Control.
  • Las lecturas del monitor de pulso no salen del dispositivo. No se guardan conversaciones.
  • La cuenta se puede borrar por completo desde el perfil (cuenta, perfil, favoritos y notas).

Cómo agregar un endpoint

  1. Esquema zod en backend/src/validation/schemas.js.
  2. Método del repositorio en memoria y en Supabase/MongoDB.
  3. Controlador y ruta (con verifyToken si es privado).
